# OCTAX

Учебная CRM-система для малого бизнеса: клиенты, сделки, задачи и статистика.

## Возможности MVP

- авторизация пользователей;
- создание, изменение, удаление и поиск клиентов;
- сделки со статусами и суммами;
- задачи со сроками и приоритетами;
- панель с основными показателями.

## Технологии

Python 3.11–3.12, Django 5.2 LTS, SQLite, Pillow и локальные CSS/JavaScript без внешних CDN.

## Обновление интерфейса V2

- люди и компании, фото или логотип, инициалы без фото;
- сетка карточек и таблица, поиск, сортировка, фильтр типа и страницы по 12 записей;
- быстрый просмотр при наведении и боковая панель по нажатию;
- тёмное меню, светлая/тёмная тема, мобильное меню и уведомления;
- суммы в тенге, реальные показатели, ближайшие задачи и последние сделки;
- быстрые действия и профиль; учтены клавиатура и уменьшение движения.

Для перехода с MVP следуйте [UPDATE_V2.md](UPDATE_V2.md).
Изображения хранятся локально в media/ и выдаются только владельцу через Django.
Не публикуйте папку media/ как общедоступную. Для резервной копии нужны и база,
и папка media/. Заменённые/удалённые фото пока остаются в хранилище без ссылки
из карточки; автоматическая очистка старых файлов в этот этап не входит.

На этом этапе нет Kanban с перетаскиванием, RU/KZ, CSV/Excel, истории действий,
глобального поиска и публичного хостинга. Сделки и задачи остаются рабочими списками.
Демонстрационные клиенты автоматически не добавляются.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Откройте `http://127.0.0.1:8000/`. Подробности архитектуры находятся в
[`ARCHITECTURE.md`](ARCHITECTURE.md).

В Windows PowerShell после создания окружения активация не обязательна:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver
```

Войдите под созданным пользователем. Новые аккаунты можно создать в `/admin/`.
Публичная регистрация не реализована. Каждый аккаунт имеет отдельный набор данных.
Пароль при вводе в терминале не отображается — это нормально.

## Проверка

```bash
python manage.py check
python manage.py test
python manage.py makemigrations --check --dry-run
```

Это локальный учебный MVP, не готовая к публичному размещению система.
Не загружайте `.venv`, базу `db.sqlite3`, пароли или настоящие клиентские данные.
Инструкция по ограничениям и настройке публикации — в ARCHITECTURE.md.

## Командная работа

Новые задачи выполняются в ветках `feature/<название>` и объединяются с `main`
через Pull Request.
