# SmartCRM — SLA/SLO (учебный проект)

Все значения ниже — **предлагаемые цели**, а не измеренные показатели. Для юридически действующего SLA нужны соглашение сторон, мониторинг и определение исключений.

| Сценарий | SLI (что измеряем) | SLO (цель за 30 дней) | Пример SLA-обязательства |
|---|---|---|---|
| Вход сотрудника | Доля успешных запросов входа при корректных данных | ≥ 99.5% | ≥ 99.0% |
| Открытие списка клиентов | Доля HTTP-ответов без серверных ошибок и с временем ≤ 1 с | ≥ 99.0% | ≥ 98.5% |
| Сохранение сделки | Доля успешных сохранений при валидных данных | ≥ 99.5% | ≥ 99.0% |

## Error budget
Для каждого SLO допустимая доля неуспешных событий = 100% − SLO. Например, при 99.5% и 10 000 корректных запросов за окно допустимо 50 неуспешных запросов; при 99.0% — 100. Нельзя автоматически переводить эти бюджеты в минуты простоя: здесь SLI событийные, а не временные.

## Измерение
В будущем добавить структурированные логи HTTP (без паролей и персональных данных), счётчики запросов и замеры latency. Исключать из знаменателя некорректные пользовательские запросы по заранее утверждённым правилам. Проверять ежемесячно. Текущая локальная версия не собирает такие метрики автоматически.
