# Лабораторная №9 — два спринта SmartCRM

## Как провести работу
1. Создать Agile-проект «SmartCRM development», два спринта с реальными датами и целями.
2. Добавить рабочие задачи. Для каждой указать описание с критериями приёмки и ответственного.
3. Передвигать задачи в Kanban в ходе работы. WIP по колонке «В работе» ограничен параметром проекта. Переходы записываются в `StatusEvent`.
4. После первого спринта записать наблюдение и **одно** измеримое действие с владельцем. Второй спринт провести с этим изменением.
5. На странице «Отчёт и CFD» сравнить throughput, средний cycle time, p85, форму CFD и узкое место. Скачать CSV для защиты.

## DoR и DoD
DoR: понятная цель, описание с критериями приёмки, назначенный ответственный, спринт. DoD: проверены критерии, выполнена проверка качества, статус «Готово».

## Данные и ограничения
При создании, смене статуса и завершении задачи сохраняется время. Throughput — число задач, остающихся завершёнными на момент отчёта. Cycle time — от первого входа в работу до последнего завершения; p85 по nearest-rank. CFD — снимки конечных состояний по календарным дням с учётом локального времени. При повторном открытии задач метрика может измениться. Данные не являются историей GitHub Projects. Для строгого условия преподавателя «экспортировано из инструмента» экспортируйте CSV из SmartCRM, приложите ссылки на доску и историю статусов или используйте реальные GitHub Projects issues. Не создавайте фальшивые значения.
